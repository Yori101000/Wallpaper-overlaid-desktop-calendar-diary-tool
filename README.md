# 透明日历（TransparentCalendar）

一个 Windows 透明桌面日历应用，设计为覆盖在已有 Wallpaper Engine 壁纸上方使用。
集月历、待办、日记与网页笔记于一体，数据全部保存在本地。

## 运行

在工程目录执行：

```powershell
dotnet run --project .\透明日历.csproj
```

也可以双击 `run.ps1`，或在 PowerShell 中运行：

```powershell
.\run.ps1
```

如果 Windows 禁止运行 PowerShell 脚本，双击 `启动透明日历.bat`。

> 应用是**单实例**的：重复启动只会把已在运行的窗口唤到前台，不会开出第二个进程
> （两个进程同时读写同一批数据文件会互相覆盖）。

## 发布为免安装运行时的单文件程序

默认运行需要目标机器装有 .NET 9 运行时。要发布成自带运行时的单个 exe：

```powershell
dotnet publish .\透明日历.csproj -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

产物在 `bin\Release\net9.0-windows\win-x64\publish\TransparentCalendar.exe`。

## 功能

### 三种视图

侧边栏切换「月历 / 待做 / 笔记」。搜索框是**在当前视图内过滤**：从月历开始搜索会自动切到列表，清空后回到月历；已经在列表或笔记里则就地过滤。

### 待办与日记

点任意日期打开编辑器，可添加待办（普通/重要）、写日记。

- **推迟**：把待办挪到次日。推迟在**点"保存"时才生效**，点"取消"可整体撤销。
  推迟天数相对最初日期累计，因此反复推迟能看出"这件事拖了多久"。
- 「待做」视图按 **逾期 / 今天 / 未来** 分组，"今天"永远全量显示，不会被积压的逾期项挤掉。

### 网页笔记

桌面端会在本机监听一个端口，接收浏览器发来的划线文本，按页面归组保存。

**方式一：安装浏览器扩展（推荐）**

1. 打开 `chrome://extensions`
2. 开启右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库的 `BrowserExtension` 文件夹

之后在网页上选中文字，右键「划线保存到透明日历」，或按 `Ctrl+Shift+S`。

**方式二：书签小工具（bookmarklet）**

在应用的「笔记」视图里复制那段以 `javascript:` 开头的代码，新建一个浏览器书签并把它粘贴到网址栏。适用于不便安装扩展的浏览器。

> **端口**：默认 `51999`；被占用时会依次向后尝试到 `52008`。应用的「笔记」视图会显示
> 实际使用的端口，扩展会自动探测整个区间，无需手工配置。
>
> **安全**：该接口只监听 `localhost`，限制请求体不超过 64KB，且只接受 http/https 的网址。
> 但请注意 bookmarklet 是从你当前页面发出的，其来源与普通网页无法区分 ——
> 也就是说**恶意网页理论上能往你的笔记里写内容**，这是 bookmarklet 方案固有的取舍。

### 窗口层级

设置里的「窗口层级」有三档：

| 取值 | 行为 |
|---|---|
| 置底 | 始终位于其他窗口之下，但**仍显示在桌面壁纸之上**。适合常驻不挡事 |
| 普通 | 与一般窗口一样参与 Z 序 |
| 置顶 | 始终压在其他窗口上方 |

窗口不会出现在 Alt+Tab 和任务栏中。

### 快捷键

| 按键 | 作用 |
|---|---|
| `←` / `→` | 上一月 / 下一月 |
| `T` 或 `Home` | 回到今天 |
| `Ctrl+F` | 聚焦搜索框 |
| `Esc` | 清空搜索；搜索已空时收起到托盘 |

## 数据位置

所有数据保存在：

```text
%AppData%\透明日历\
```

| 文件 / 目录 | 内容 |
|---|---|
| `settings.json` | 界面与行为设置 |
| `calendar-data.json` | 待办与日记 |
| `web-notes.json` | 网页笔记 |
| `backups\` | 自动备份（每天一份，保留最近 20 份） |
| `logs\` | 运行日志（保留最近 7 天） |

设置窗口里有「打开本地存储位置」按钮，可以直接打开这个文件夹。

**数据保护**：所有写入都是先写临时文件再原子替换，中途崩溃不会把文件写坏；
万一某个文件仍无法解析，它会被改名为 `*.broken-<时间戳>.bak` 隔离保留，应用启动时会提示你，
可从 `backups\` 恢复。设置窗口也提供手动的导出 / 导入备份。

## 开发

```powershell
dotnet build .\透明日历.csproj                      # 构建（应保持 0 警告 0 错误）
dotnet test .\Tests\TransparentCalendar.Tests.csproj # 单元测试
```

测试覆盖存储层（原子写入、损坏隔离、备份策略）、设置迁移、网址校验与日历查询等纯逻辑，
全部在临时目录中运行，不会触碰 `%AppData%` 里的真实数据。

架构说明见 `CLAUDE.md`。
